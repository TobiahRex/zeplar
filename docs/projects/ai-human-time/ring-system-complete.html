⚛️ 1. Core Philosophy

The fundamental insight that drives the entire system

ring_speed = base_rate × (1 - impedance)

🎯 The Goal

Keep all rings spinning continuously at maximum velocity. A human observer should be able to glance at the dashboard and instantly know:

  • Which agents are running optimally
  • Which agents are slowed or stopped
  • What impediments are causing the slowdown
  • What actions will restore full speed

🔑 Key Insight

Different agents have different "clock speeds" (productivity rates). The effort is invariant—it's the same work. But the time to complete it varies by agent.

Human (1x): 80 hours → 2 weeks
AI (20x): 80 hours → 4 hours

💡 The Human's Role

The human observer's job is to identify and eliminate impedances so that rings spin continuously at max speed. The visual UX should make impedance sources immediately obvious, provide actionable insights, and enable faster resolution.

Agent

An AI worker with a base productivity rate. Tracks current velocity after impedance is applied.

Ring State

The visual representation of an agent's velocity. Controls animation speed, color, and status.

Impediment

An active blocker affecting an agent's velocity. Has a measurable impact (0-1).

Impediment Type

Classification with default impact and resolution metadata (auto-resolve, requires human, etc.).

🎨 5. Visual Design

Ring behaviors and dashboard layout principles

Ring Behavior States

✅ Optimal

Ring spins fast and smooth. Bright color, high opacity. This is the goal state.

duration: 1.5s, opacity: 0.9, color: #4ade80

🐢 Throttled

Ring spins slowly but continuously. Dimmer, yellow tint. Needs attention.

duration: 6s, opacity: 0.7, color: #f59e0b

🛑 Blocked

Ring completely stopped. Pulsing warning indicator. Requires immediate action.

duration: ∞ (paused), opacity: 0.4, color: #ef4444

⚙️ Stuttering

Ring moves but with visible micro-pauses. Minor friction present.

keyframes with pauses, opacity: 0.8, color: #8b5cf6

💻 6. Implementation

TypeScript implementation and interactive demos

Core API

const monitor = new RingMonitor();

// Register agents
monitor.registerAgent({ 
  id: 'agent1', 
  name: 'Coder', 
  baseRate: 20 
});

// Add an impediment (ring will slow/stop)
monitor.addImpediment('agent1', 'rate_limit');

// Resolve it (ring resumes)
monitor.resolveImpediment(impedimentId);

// Get system-wide metrics
const metrics = monitor.getSystemMetrics(127);
// → { systemVelocityPercent: 78, lossToBlocking: 12, ... }

// Get ring animation parameters for UI
const ring = monitor.getRingParameters('agent1');
// → { duration: '1.5s', color: '#4ade80', opacity: 0.9 }

🎯 Design Summary

The Problem

AI says "2 weeks" but means effort, not time. Humans need visibility into what's slowing AI workflows.

The Solution

Visualize each agent as a spinning ring. Ring speed = productivity. Impediments visibly slow or stop rings.

The UX Principle

One glance tells you: system health, problem agents, specific impediments, and resolution actions.

The Goal

All rings spinning at max speed, continuously. Human's job: eliminate impedances to restore velocity.

🎯 Maximize: Σ(agent.velocity) / Σ(agent.base_rate)
System Velocity = Current Output / Theoretical Maximum
