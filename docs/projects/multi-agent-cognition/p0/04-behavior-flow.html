📡 WebSocket Protocol Specification

WS Client → Server Messages
Type Payload Purpose
SUBSCRIBE { oci_ids: string[] } Join org instance streams
UNSUBSCRIBE { oci_ids: string[] } Leave org instance streams
TASK_SUBMIT { oci_id, task: TaskDef } Submit new task to org
TASK_CANCEL { task_id: string } Cancel running task
AGENT_OVERRIDE { agent_id, action } Human intervention
PING { ts: number } Keep-alive heartbeat
WS Server → Client Messages
Type Payload Purpose
AGENT_STATE { agent_id, state, ts } Agent lifecycle update
TASK_PROGRESS { task_id, pct, msg } Task execution progress
TASK_COMPLETE { task_id, result } Task finished
ORG_STRUCTURE { oci_id, graph } Full org snapshot
LLM_STREAM { agent_id, chunk } Token stream relay
ERROR { code, msg, ctx } Error notification
PONG { ts, latency } Heartbeat response

⚡ Behavioral Insights

1. Checkpoint Density: Every state transition writes to DB — enables replay from any point.

2. Parallel Execution: Sibling agents (FE/BE) execute concurrently; parent waits for all children.

3. Stream Relay: LLM token streams pass through to WebSocket for real-time UI updates.

4. Event Coalescing: High-frequency events (tokens) are batched before WS transmission.
