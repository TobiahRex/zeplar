⚠️ Failure Scenarios & Recovery Strategies

🔌 Connection Drop

WebSocket disconnection during active workflow

  • Workflow continues server-side
  • Events buffered in memory (5min TTL)
  • Reconnect replays missed events
  • Client syncs from last known sequence
// Reconnection protocol
RECONNECT {
  session_id: "...",
  last_seq: 42
}

💥 Agent Crash

Agent process dies mid-execution

  • Supervisor detects heartbeat loss
  • Load last checkpoint for agent
  • Spawn replacement agent
  • Restore state + replay pending
// Heartbeat config
HEARTBEAT_INTERVAL: 5s
HEARTBEAT_TIMEOUT: 15s
MAX_RESTARTS: 3

🗄️ Database Failover

Primary PostgreSQL becomes unavailable

  • Connection pool retry with backoff
  • Read replica promotion
  • Queued writes replayed on recovery
  • Idempotent operations ensure safety
// Retry policy
INITIAL_BACKOFF: 100ms
MAX_BACKOFF: 30s
MULTIPLIER: 2.0

🤖 LLM Timeout

LLM API call exceeds timeout threshold

  • Circuit breaker opens after N failures
  • Fallback to cached/default response
  • Agent enters BLOCKED state
  • Escalate to parent for decision
// Circuit breaker
FAILURE_THRESHOLD: 5
RESET_TIMEOUT: 60s
HALF_OPEN_REQUESTS: 3

🔄 Infinite Loop

Agent stuck in delegation/retry cycle

  • Max iteration guard per task
  • Cycle detection in task graph
  • Timeout kills and escalates
  • Dead letter queue for analysis
// Loop protection
MAX_ITERATIONS: 100
TASK_TIMEOUT: 5m
WORKFLOW_TIMEOUT: 1h

🏢 Tenant Isolation Breach

Cross-tenant data access attempt

  • Row-level security in PostgreSQL
  • Tenant ID in all queries (enforced)
  • Connection pool per tenant
  • Audit log + immediate alert
-- RLS policy
CREATE POLICY tenant_iso
ON checkpoints
USING (tenant_id = current_tenant())

🚨 Critical Alert Definitions

🔴 Agent Stuck Alert

Condition: Agent in same state > 5 minutes
Severity: Critical
Action: Force checkpoint + restart agent

alert: AgentStuck
expr: agent_state_duration_seconds > 300
for: 1m
labels:
  severity: critical

🔴 Checkpoint Lag Alert

Condition: No checkpoint in workflow > 30 seconds
Severity: Warning → Critical
Action: Investigate DB connection

alert: CheckpointLag
expr: time() - last_checkpoint_ts > 30
for: 30s
labels:
  severity: warning

✅ Resilience Guarantees

1. At-least-once delivery: Events may replay on recovery, operations must be idempotent.

2. Bounded data loss: Maximum 1 checkpoint interval (~2s) of work can be lost.

3. Automatic recovery: System self-heals within 30s of most failure types.

4. Full auditability: Every state change logged with correlation IDs for reconstruction.
