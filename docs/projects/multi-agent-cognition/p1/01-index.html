🧠 Core Concepts

🏢 Tenant Isolation

Each customer operates in a fully isolated environment with dedicated database schemas, event channels, and agent pools. Row-level security ensures zero data leakage.

📊 Org Chart Instance (OCI)

A single hierarchical agent graph representing one workflow. Multiple OCIs can run concurrently within a tenant, each with its own task graph and state.

🤖 Agent Roles

Human-proxy archetypes (CEO→Intern) defining capabilities, authority levels, and delegation permissions. Parents task children; verification flows upward.

💾 Checkpoint Recovery

Every state transition persists to PostgreSQL before acknowledgment. On failure, system replays from last valid checkpoint with deterministic state restoration.

📬 Event Bus Bridge

PostgreSQL NOTIFY feeds internal pub/sub which transforms and routes to WebSocket connections. Enables real-time client updates from database changes.

🔗 Distributed Tracing

OpenTelemetry spans propagate through entire agent hierarchy. Every LLM call, task delegation, and checkpoint is traced for debugging and optimization.

⚠️ Friction Points & Solutions

🎯 Managing Concentric Temporal Cycles

⏱️

UX Expectation vs. System Reality

Users expect immediate feedback, but LLM calls take 1-10s, tasks take 10-60s, and workflows take minutes. The temporal mismatch creates perceived latency.

✅ Solution: Progressive state projection with optimistic UI updates. Stream LLM tokens directly to client. Show predicted completion states.
🌊

Event Flood from Inner Cycles

LLM token streams generate ~50 events/second. Naive propagation would overwhelm WebSocket connections and client rendering.

✅ Solution: Event coalescing at WebSocket bridge. Batch token chunks, debounce rapid state changes, use backpressure signals.
🔄

Checkpoint Frequency vs. Performance

Checkpointing every state change ensures minimal data loss but adds latency. Sparse checkpoints risk losing significant work on failure.

✅ Solution: Tiered checkpointing — fast in-memory checkpoints for inner cycles, durable DB checkpoints at task boundaries.
👥

Multi-OCI Multiplexing

Single WebSocket connection must handle events from multiple org charts without confusion. Event ordering and routing become complex.

✅ Solution: Namespaced event channels with OCI prefixes. Client-side subscription management. Server-side fan-out based on active subscriptions.

🎯 Design Principles

01

Checkpoint-First Durability

Every state mutation writes to PostgreSQL before returning success. This "persist-then-proceed" pattern ensures workflow recovery from any failure point.

02

Hierarchical Autonomy

Each agent manages its own state machine independently. Parents orchestrate but don't micromanage. This enables parallel execution and reduces coordination overhead.

03

Protocol Translation at Boundaries

Internal event formats are decoupled from client protocols. The WebSocket bridge is the single translation point, enabling protocol evolution without breaking clients.

04

Observable by Default

Every component emits structured telemetry. Tracing spans propagate through the full call chain. You can reconstruct any workflow from logs alone.

⚖️ Key Trade-offs

Decision Benefits Costs Mitigation
PostgreSQL NOTIFY for Event Bus Transactional consistency, no separate infrastructure Limited throughput (~10K events/s), single point Horizontal scaling via tenant sharding, Redis fallback for high-volume
Checkpoint per State Change Minimal data loss (~2s max), deterministic recovery ~50ms latency per checkpoint, storage growth Async checkpoint batching, TTL-based cleanup, tiered storage
Hierarchical Agent Model Intuitive org mapping, clear authority chains Deep trees add latency, bottleneck at root Parallel sibling execution, skip-level delegation for urgent tasks
WebSocket per Client Real-time bidirectional, connection multiplexing Connection limits, reconnection complexity Event buffering, sequence-based replay, graceful degradation to polling
Multi-Tenant Single Cluster Resource efficiency, simpler operations Noisy neighbor risk, blast radius on failure RLS isolation, per-tenant resource limits, dedicated pools for enterprise
